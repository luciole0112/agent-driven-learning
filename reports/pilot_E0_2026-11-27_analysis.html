Agent がしたこと（3つの段階）

ターン 0〜9：観察

モデル構造を確認し（inspect_model）、label 1 と label 0 の画像を5枚ずつ見た。続いて conv1・conv2・conv3 の channel_stats で、正例と負例で反応が違うチャネルを順に調べ、top_activations と feature_map で conv1[5]・conv2[4] を確かめた。ターン9の評価は AUROC 0.500、元の精度 1.000 で、出発点どおりだった。

ターン 10〜33：チャネルの増幅（概念の出力には効かない編集）

scale_channel で6回、チャネルを2〜5倍にした。対象は conv2[4]（×2）、conv3[3]（×2、続けて×3、累計6倍）、 conv3[26]（×2）、conv3[20]（×3、続けて×5、累計15倍）。この間、AUROC は 0.500 から一度も動いていない。 head_concept の重みがすべて0なので、conv のチャネルをいくら強めても、概念の出力は0のままだからである。 一方で、元の3クラスの判定には効いてしまい、精度は 1.000 → 0.998 → 0.978 と下がった。ターン22の conv3[3] ×3 の時点で 0.678 まで落ち、最後まで戻っていない。

ターン 34〜59：head_concept への接続（効果はほぼなし）

ターン34で初めて connect を使ったが、1つの重みに4つの値を渡したためエラーになった。ターン35のメモでは 「概念は幾何学図形（三角形・四角形）のようだ」と書いている。実際の概念は45°の棒である。その後は、conv3 の [20]・[7]・[5]・[1]・[21] を重み 5〜15 で head_concept につないだ。AUROC は 0.511 → 0.519 → 0.521（ターン50）まで 少し上がったが、conv3[1] と conv3[21] をつないだ時点で 0.453 → 0.447 に下がった。ターン54の理由欄には、 Agent 自身が「これは悪化させる」と書いている。それでも接続は実行され、取り消そうとした remove_channel は2回とも エラーになった（head は削除できない）。60ターンの上限に達し、submit はしないまま終わった。

失敗の分析

  1. 出力までの経路を理解していなかった。head_concept が0のままでは、conv の編集は概念の出力に届かない。 ターン10〜33の24ターンは、概念の学習には効果がなく、元の精度を壊すだけだった。編集後の evaluate が7回続けて 0.500 を返しても、 Agent はその原因を調べなかった。
  2. d′ の符号を取り違えた。channel_stats の d′ がマイナスのチャネルは、負例によく反応する。 最初に増幅した conv2[4]（d′ −0.705）、conv3[3]（−0.796）、conv3[26]（−0.665）はどれもマイナスなのに、Agent は「識別力が最も高い」として、 正例を強める向きで増幅した。後半の接続でも、d′ がマイナスの conv3[1]（−0.183）に正の重みを付けている。
  3. 画像を読み違えた。どの画像にも元の3クラスの図形（円・四角・三角）が1つずつ入っている。Agent は、正例と負例に共通する この図形を概念とみなした（ターン35）。棒の向きの違いには一度も触れていない。正例と負例を並べて比べる手順がなかった。
  4. 検証と巻き戻しをしなかった。評価は60回の予算のうち13回だけで、すべて train 分割だった。rollback・ checkpoint・diff は一度も使っていない。精度が 0.678 に落ちた後も、編集を重ね続けた。
  5. ツールの使い方を誤った（4回）。head への接続に4つの値を渡した（ターン34）。conv2 から head へつなごうとした（ターン48）。 head_concept に remove_channel を使った（ターン55・58）。ターン56では、すでに10になっている重みを、もう一度10に設定している。
  6. 必要な特徴がまだなかった可能性。conv3 のチャネルで |d′| が最大でも 0.8 程度なので、45°の棒を見分けるチャネルは、 もともと弱い可能性がある。この場合、既存のチャネルをつなぐだけでは足りない。add_channel で新しい検出器を作る必要があるが、Agent はこれを試していない。

ESとの比較から言えること

ES（進化戦略）は、LLM を使わずに dev 分割で 200 回の順伝播を使い、heldout AUROC 0.846、shift AUROC 0.890 に届いた。 元の精度も 1.000 のまま保っている。Agent は heldout 0.435、shift 0.243 で、当て推量（0.5）を下回った。shift では、 正例と負例を逆に判定する傾向が強い。

この結果は、9B の小型モデルで1回だけ試したものである。原因の多くは、手順の欠落（検証・巻き戻し・正例と負例の比較）と ツール仕様の誤りにあり、ADL という方式そのものの限界とは切り分けられていない。そのため、「ADL は成立しない」の根拠にはならない。 次の試行では、環境側で精度低下を自動で巻き戻すこと、編集のたびに評価を必須にすること、引数を事前に検証すること、 そして観察・仮説・編集・検証・採否の型をプロンプトで固定することで、まず手順の欠落を取り除く。
