課題

元の3クラス（円・四角・三角）を学習済みの小さなCNNに、新しい2値概念を教える。勾配も最適化器も使わず、 Agent がツールで内部を観察し、重みを直接編集する。head_concept の重みは最初すべて0で、 そのままなら AUROC は 0.5 になる。

正解の概念：45°の向きの棒（色はランダム）。負例には 90°・135°・180° の棒が入る。背景にはどの画像にも、元の3クラス（円・四角・三角）の図形が1つずつある。 Agent には概念を教えていない。

評価に使う heldout（1000枚）と shift（500枚、明るくノイズの多い背景・大きい棒）は、Agent からは見えない。

Agent が show_examples で実際に見た画像を、同じ乱数シードから再生成した。

Agent がしたこと

ターン1〜2で、正例と負例を20枚ずつ見た。その後は観察と1回の編集を交互に繰り返し、7回の仮説・編集・評価・採否のサイクルを回した。 7回とも dev の AUROC が改善せず（0.500 または 0.493）、Agent は自分で「棄却」を選んだ。環境はそのたびに編集を元に戻した。 最後の仮説（ターン59）は、60ターンの上限で編集に進めなかった。最終モデルは初期と同じ重みのままで、どの指標も 0.500 になった。

  • conv3[20] ×2 の増幅を3回（ターン7・32・48）、conv3[20] → head_concept の重み1.5の接続を2回（ターン18・54）試した。どれも同じ編集で、同じ結果だった。
  • conv1[6]・conv3[5] の増幅も試した。conv1[6] は head_concept に直接つなごうとして、2回とも引数の検証で止められた（head につなげるのは conv3 だけ）。
  • 仮説の前に編集しようとした（ターン37）、評価の前に次の仮説を立てようとした（ターン49）。この2回は、手順違反として阻止された。

分析

  1. ガードレールは意図どおりに働いた。元の精度は最後まで 1.000 で、前回のような破壊は起きなかった。評価は train ではなく dev に移り、 すべての編集に仮説・評価・採否が記録された。自動ロールバックは一度も発動していない。編集が小さかった（倍率2、重み1.5）からである。
  2. 学習はまったく進まなかった。7回の編集はすべて棄却され、概念の性能は当て推量のままだった。前回の 0.435 より 0.5 に近いのは、壊れなかったからにすぎない。 概念を学べるようになったわけではない。
  3. 仮説は画像の比較ではなく、統計の数字に頼っていた。手順上は正例と負例を見ている。しかし、仮説の「正例の根拠」欄に書かれているのは、d′ の値と「どの画像で反応したか」という活性化の数値だけで、棒の向きや形といった 見た目の違いには一度も触れていない。比べる手順を強制しても、比べた中身までは強制できていない。
  4. 失敗から学んでいない。同じ増幅を3回、同じ接続を2回繰り返した。棄却の理由に「接続が必要」と書きながら、次のサイクルでまた増幅に戻っている。 head_concept が0のままでは増幅が効かないことも、まだ理解していない。
  5. 既存のチャネルには、使える特徴がほとんどない。conv3 で正の d′ が最大のチャネルでも d′ は +0.17 程度で、1本つないでも dev AUROC は 0.493 だった。 45°の棒を見分けるには、複数のチャネルの組み合わせ（負の重みを含む）か、add_channel で新しい検出器を作る必要がある。Agent はどちらも試していない。

これも 9B モデルでの1回きりの試行である。ガードレールで「壊さない」ことは確保できた。 一方で、「学ぶ」ための壁として、画像の比較、失敗の記憶、編集の種類の狭さが残っている。
