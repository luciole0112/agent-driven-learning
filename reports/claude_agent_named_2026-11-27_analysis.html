この結果の位置づけ（必ず先に読むこと）

  • これは「名前のある特徴を、人間並みの視覚の知識で設計したときの上限」に近い参照値である。名前のない特徴を学習できることを示すものではない。研究の中心の問い（E1：名前のない glyph をデータから獲得できるか）には、この結果は答えていない。
  • Agent（Claude）は、実験の前にリポジトリのコードを読んでいる。その中にはデータ生成器（adl/data/shapes.py）も含まれ、負例の棒が 45° ずれた向き（90°・135°・180°）であること、shift 分割では棒が太くなり背景が明るくノイズが多くなることが書かれている。設計は画像の観察から説明できる範囲に留めたが、事前知識が混入していることは否定できない。
  • 設計の候補は、Agent 用のサンドボックス（NumPy のみ）で、train と dev の画像に対して少数の手設計案（各回2〜12案）を試算して選んだ。最小二乗・逆行列・反復更新などの当てはめは使っていない（監査フラグ：{audit}）。ただし dev を試算に使ったので、dev の値は楽観的である。封印された heldout と shift が本当の評価である。
  • ベースCNN はクラウドの CPU で学習し直したもので、前回 PC 上で VLM が使ったベースとは重みが違う。ES は今回のベースで再実行した（heldout 0.845、PC では 0.846）。

結果

Claude が環境のツールを Python から直接呼び出し、勾配を一切使わずに、heldout AUROC 0.9999、shift AUROC 0.994 に到達した。元の3クラス精度は 1.000 のままである。既存の重みは1つも変えず、新しいチャネル4本（conv1 に2本、conv2・conv3 に1本ずつ）と、その間の接続だけを書き込んだ。dev の評価は9回、編集は8回（うち1回は引数の形のエラーで未適用、採用7、棄却0）だった。

なぜ私（Claude）はこの概念を認識できるのか

正例と負例の画像（下図）を見て、私が「45°の棒がある」と判断するときに実際に使っている手がかりを、できるだけ具体的に書き出した。右の列は、それをCNNのどの内部表現として組み込んだかである。

{pos}{neg}
私が見ている手がかり組み込んだ内部表現
1. 図と地：暗いノイズの背景の上で、いちばん明るい「線」に目が行く。円・四角・三角は大きく、正例にも負例にも同じように出るので無視する。大きな一様領域には反応しない「総和0」のカーネル（conv1[8]）。中心の線が+、両側が−。
2. 色は関係ない：棒の色は白・桃・黄緑など毎回違う。明るさで見ている。RGB 3チャネルに同じ重み（＝輝度）。
3. 細さ：幅1〜2画素で、長さは9画素以上。両側が暗い「線」であって、領域の縁（片側だけ明るい）ではない。中心線の両側に負の重み。縁への応答は線の半分になる。
4. 向き：左下から右上へ伸びる（/）。—・|・\ は同じ明るさ・細さでも違う。反対角線（i+j=4）だけを+にした 5×5 の方位選択カーネル。合成の棒で試算すると / に 5.0、—・| に 1.0。
5. 連続性：点が1つ明るいだけでは棒ではない。/ 方向に点が並んでいる。conv2[16]：conv1[8] の反応を、プール後の格子で / 方向の3点（右上・中央・左下）足し合わせる共線連結。
6. 向きの競合：\ の棒を見ると、「/ ではない」と即座にわかる。逆向きがはっきり見えるから。conv1[9]（\ 検出器）を作り、conv2[16] で3×3近傍を −1 で差し引く対抗抑制。
7. 位置によらない：棒は画像のどこにあってもよい。畳み込みの平行移動不変性と global max pool。conv3[32] は conv2[16] をそのまま通し、head_concept に重み 1.0 でつなぐ。

1〜5 と 7 は最初の観察で言語化した。6 は dev の誤りを見て初めて自覚した手がかりである（step 47）。また「図形の上でコントラストが低くても見える」ことも、誤りを見て気づいた（step 35）。

組み込んだ回路

{kern}
入力 RGB
 └ conv1[8]  / 線検出（輝度、5×5、bias −0.6） ─┐
 └ conv1[9]  \ 線検出（輝度、5×5、bias −0.6） ─┤ maxpool
                                               ↓
   conv2[16] = ReLU( Σ_/方向3点 conv1[8] − Σ_3×3 conv1[9] − 1.0 )
                                               ↓ maxpool
   conv3[32] = ReLU( conv2[16] の中心 )
                                               ↓ global max pool
   head_concept = 1.0 × conv3[32]

既存の8＋16＋32チャネルへの入出力の重みはすべて0のままなので、元の3クラスの予測は数学的に変わらない。ablation（step 59〜61）では、conv1[8] を消すと dev AUROC は 0.9998→0.500、conv1[9] を消すと 0.9963、既存の conv1 の8チャネルをすべて消しても 0.9998 のままだった。概念の判断は、新しく作った経路だけが担っている。

観察・推論・編集の流れ

  1. 観察（step 0〜11）：正例・負例16枚ずつ、conv1 のカーネル、既存チャネルの反応差を見た。既存の conv3 で正例に強く反応するチャネルはなく（正の d′ は最大 +0.16）、使える特徴はないと判断した。画素値を読むと、棒は輝度 0.6〜0.9、背景は 0.1〜0.2 で、1画素幅のきれいな斜めの階段だった。
  2. 設計の試算（step 9、11）：自分で描いた合成の棒で3種類のカーネルの方位選択性を比べ、train の画像で「検出→共線連結→全域 max」の流れを試算した（train AUROC 0.999〜1.000）。
  3. サイクル1〜4（step 12〜32）：検出器（conv1[8]）→共線連結（conv2[16]）→受け渡し（conv3[32]）→ヘッドへの接続、の順に1つずつ組み込んだ。最初の3つは出力側が0なので AUROC は 0.500 のままと予測し、その通りだった。代わりに channel_stats と特徴マップで、新しいチャネルが / の棒だけに反応することを確かめてから採用した。ヘッドにつないだ時点で dev AUROC は 0.981 になった。
  4. 誤りの分析とサイクル5（step 33〜44）：取りこぼした正例8枚を見ると、すべて明るい図形の上の棒だった（下図左）。輝度差が小さく、bias −1.0 で切られていた。bias をノイズの約3σ（−0.6）に下げ、dev AUROC は 0.996 になった。試算では −0.3 の方が dev では良かったが、shift のようなノイズの多い画像で誤反応が増えるおそれがあるので採らなかった。
  5. 誤りの分析とサイクル6〜7（step 45〜58）：今度は、太く明るい \ の棒の負例が誤反応した（下図右）。/ 検出器は \ の太い棒にも弱く反応し、閾値を下げたことで棒に沿った弱い応答がつながってしまった。\ 検出器を作って対抗抑制をかけ、dev AUROC は 0.9998 になった。dev がほぼ飽和したので、それ以上の調整は dev への過適合になると考えて提出した。

分析

何が VLM との差を生んだか

  • 画像の比較を仮説に書けたこと。前回の VLM の仮説は d′ などの数字だけで、棒の向きには一度も触れなかった。今回は「明るく細い線が / 方向」という見た目の違いをそのまま仮説にし、それをカーネルの形に翻訳した。
  • 編集の種類。VLM は既存チャネルの増幅と1本の接続を繰り返した。既存のチャネルには向きの情報がほとんどなく（d′ ≤ +0.16）、それでは学べない。今回は add_channel で conv1 から新しい経路を作った。決め手は「どこに何を作るか」の選択だった。
  • 誤りから学んだこと。dev の誤りの例を実際に見て、そのたびに原因（低コントラスト、逆向きの太い棒）を言語化し、それぞれに1つの編集で対処した。同じ編集の繰り返しは一度もない。

編集空間と知識の寄与を分けると

ES の既定（新しい conv3 チャネル1本）は heldout 0.845 で止まる。同じ conv3 の空間では、逆伝播でも学習は進まなかった（0.499）。conv2 までの既存の特徴に向きの情報がないためだと考えられる。

一方、Claude と同じ編集空間（conv1 に2本・conv2・conv3 に1本の新しい経路、約400パラメータ）をランダムな初期値から ES で埋めると、heldout は seed によって 0.992・0.846・0.823 になった。つまりこの概念では、編集空間の選び方そのものが大きく効いている。知識が加えたのは、(1) その編集空間を選んだこと、(2) dev の評価9回で確実に到達したこと（ES は200回の順伝播で、3回に1回だけ 0.99 に届いた）、(3) shift でも 0.994 と頑健だったこと（ES の最良 seed は 0.933）、(4) 各重みに意味の説明がつくこと、の4点である。同じ空間での逆伝播の参照値は、今回の設定（ランダム初期値、lr 1e-2・1e-3、1000 ステップ）では3 seed とも学習が進まず、確立できなかった。初期化を調べ直す必要がある。

「思考プロセスをモデルに組み込む」とは何だったか

組み込めたのは、私の視覚の手がかりのうち、局所的で、言葉で説明でき、畳み込みで表せるもの（明るさ・細さ・向き・連続性・向きの競合・位置不変）である。これは V1 の単純型細胞と、方位どうしの側抑制に近い、古典的な手設計の検出器である。一方で、私の認識が実際にどう計算されているかを内省で正確に知ることはできない。上の表は「私が判断の根拠として言語化できる手がかり」であって、私の内部の計算の写しではない。

そして、この方法は「手がかりに名前を付けられる」ことに依存している。名前のない glyph では、手順のうち「見えている手がかりを言葉にする」段階が使えない。研究として次に確かめるべきなのは、観察→誤りの例を集める→正例と負例の差を見つける→検出器を作る→誤りを見て競合を加える、という手順の部分が、名前のない特徴でも働くかどうかである。

環境について見つかったこと

  • set_weights で0次元の要素（例：conv1.bias の1要素）に values=[-0.6] を渡すと、形の不一致でエラーになる（step 40）。スカラー -0.6 なら通る。引数の検証で弾くか、1要素の配列を受け付けるように直すとよい。この失敗の後、検証の手順上 evaluate を1回余分に使った（step 41）。
  • 既存の逆伝播の参照（backprop_channel）は conv3 の1チャネルしか動かさないので、この概念の上限の参照としては弱い。conv1 から経路を作れる参照が必要である。
