## 0. 方針の要点

1. **研究の焦点を1点に絞る。** 「Agentが勾配なしでネットワーク内部を編集できるか」は、Weight-Space Programming（WSP）の一連の研究ですでに示されている。本研究はその先にある問い、つまり **「Agentは、自分も名前を知らない新しい特徴をデータから発見し、永続的に獲得できるか（＝学習できるか）」** を中心に据える。
2. **「Agentが学習主体である」ことを、測れる形で定義する。** 主張は哲学的にせず、情報源のアブレーションと、同じ予算のゼロ次最適化との比較で判定する。
3. **早く、小さく、否定しうる形で始める。** 最初の実験は、仮説が誤っていればすぐ分かるように設計する。否定的な結果も、WSPの限界を示す知見として価値がある。
4. **速度を重視する。** この分野は週単位で論文が出ている。arXivの監視を続け、重なる研究が出たら方針を即座に見直す。

## 1. 研究の問い

### 中心的な問い（RQ0）

> 凍結されたLLM/VLMを基盤とするAgentは、誤差逆伝播を使わずに、データの観察と内部表現への直接操作だけで、**自身の事前知識に名前のない特徴**をニューラルネットワークに獲得させられるか。

### 下位の問い

| ID | 問い | 対応する仮説 |
|---|---|---|
| RQ1 | 名前のない特徴を、少数のデータから獲得できるか | H3（反仮説：既知特徴の再生しかできない）の検証 |
| RQ2 | Agentの意味的知識と内部観察は、学習の効率にどれだけ寄与するか | H1：探索の有効次元を減らし、同じ評価予算でゼロ次最適化を上回る |
| RQ3 | Agentの学習は、固定則（matched filter、最小二乗など）の呼び出しや、試行錯誤の探索に退化していないか | — |
| RQ4 | 多層にまたがる特徴を、中間層の目標を意味的に定義することで形成できるか | H2：意味的な credit assignment |
| RQ5 | 獲得した能力は、Agentを外した後も保持され、分布シフトに汎化し、既存能力を壊さないか | — |

RQ1〜RQ3 を最初の到達目標とする。RQ4 と RQ5 の一部（継続学習）は次の段階で扱う。

## 2. 用語と操作的定義

### 2.1 「学習した」の定義

次の4条件をすべて満たすとき、「Agentがモデルに特徴 X を学習させた」とみなす。

- **(L1) 獲得**：初期状態で X を検出できない（AUROC ≈ 0.5）モデルが、封印した held-out で X を検出できる。
- **(L2) 永続性**：獲得した能力が重み・構造の変更として残り、Agentなしで動作する。
- **(L3) 汎化**：位置・スケール・背景の分布シフトに対しても検出できる。
- **(L4) 保持**：既存タスクの性能低下が、事前に決めた許容幅に収まる。

### 2.2 「Agentが学習主体である」の定義

上の (L1)〜(L4) に加えて、次の2条件を満たすときに限り、「Agentが学習主体として機能した」と主張する。

- **(P1) 情報源への依存**：意味情報を除いた条件、または内部観察を除いた条件で、性能が統計的に有意に低下する。
- **(P2) 標本効率**：同じ操作空間・同じ順伝播予算で、ゼロ次最適化（ES、CMA-ES）を有意に上回る。

(P1) と (P2) がどちらも成り立たない場合は、「Agentは汎用の探索器として働いた」と結論する。

### 2.3 許容する計算と禁止する計算（v1 の暫定ルール）

| 区分 | 扱い |
|---|---|
| 対象モデルのパラメータに対する勾配、optimizer | **禁止**（サンドボックスで遮断する） |
| ベースモデルを逆伝播で事前学習すること | 許容（新概念とは無関係な基礎タスクに限る） |
| 対象モデルの入力に対する勾配（saliency） | **v1 では禁止**。後で、許可した条件を別の実験因子として追加する |
| Agentのコード内での最小二乗・回帰・PCA | **許容するが、自動で検知してフラグを付ける**。加えて、全面禁止の条件（条件 H）を設ける |
| 順伝播・評価 | 許容。回数に予算を設け、計量する |
| Agentによる評価指標の利用 | 許容（方針 §6） |

この表は ChatGPT との検討事項でもある（§8）。

## 3. 段階的な計画と判断ゲート

各段階の終わりに判断ゲートを置く。ゲートを通らなければ、次の段階には進まずに方針を見直す。

### Stage 0：先行研究の精読と環境構築

- **内容**
  - 最も近い2本を精読する：Ropinski & Kranz（arXiv:2611.26408、CNN/ViT の道具による編集）と iWSP（arXiv:2611.18114、反復的な重みの記述）。E1 と重なる実験がないか、ツール仕様と評価の作法を確認する。
  - 観察・介入・数値演算・永続操作・検証・記憶のツール群（報告第1版 §3）の最小版を実装する。
  - 計量と監査の仕組み：順伝播回数、重みへの演算量、当てはめ演算の検知、勾配の遮断。
  - データ生成器と、凍結するベースCNNを作る。
- **ゲート G0**
  - 精読の結果、E1 とほぼ同じ実験がすでに報告されていないこと。報告されていた場合は、問いを RQ4（階層）か RQ2（効率の分解）へ移す。
  - 勾配の遮断と当てはめ検知が、テストで正しく動くこと。

### Stage 1：パイロット（E0）

- **内容**：**名前のある**単純な特徴（例：特定の向きの線分）を後から獲得させる。条件は A（Full Agent）と F（matched filter）のみ。
- **目的**：環境・ツール・評価の配線確認。ここでの成功は研究上の主張にはならない（既知特徴の書き下しにすぎないため）。
- **ゲート G1**：A が (L1)(L2) を満たすこと。満たさなければ、ツールや操作空間の設計を直す。

### Stage 2：中心実験（E1）

- **内容**：名前のない局所パターンの後付け獲得。詳細は §4。
- **ゲート G2**（事前登録した基準で判定する。§5）
  - **成立**：(L1)〜(L4) と、(P1) または (P2) を満たす → Stage 3 へ進む。
  - **部分的成立**：(L1)〜(L4) は満たすが、(P1)(P2) を満たさない → 「Agentは探索器として学習できるが、意味知識は効いていない」と結論する。そのうえで、意味知識が効く条件（自然画像、より大きな操作空間）を探るか、問いを効率の分析へ移す。
  - **不成立**：(L1) を満たさない → H3 を支持する結果として整理する。WSPの限界（「持っていない能力は加えられない」）の体系的な検証として報告し、どこで失敗するかを分析する。

### Stage 3：階層と credit assignment（E2）

- **内容**：「部品 P と Q が特定の配置にある」ことを新概念とし、2層にまたがる形成を要求する。Agentが中間層の目標を意味的に定義する条件と、定義させない条件を比べる（H2）。
- **ゲート G3**：中間目標の定義が、獲得の成否または効率に有意な差を生むこと。

### Stage 4：継続学習と自然画像（E3, E4）

- **内容**：複数の概念を順に獲得させ、忘却と表現の再利用を測る（E3）。人物検出の部位特徴など、自然画像の課題に移る（E4）。
- **注意**：E4 では「既知の知識の書き下し」と「データからの学習」の区別が難しくなる。E1〜E3 で確立した判定方法を前提に進める。

## 4. 最初の中心実験 E1：名前のない局所パターンの後付け獲得

### 4.1 データ

- 64×64 の合成画像。背景はランダムなテクスチャや図形。
- **基礎概念**：円・四角・三角などの分類。ベースCNNを逆伝播で学習してから凍結する。
- **新概念 X**：手続き的に生成する、意味的な名前を持たない局所構造。位置・スケール・回転をばらつかせて配置する。
  - **名前のなさ**を担保するために、X の候補を複数作り、事前に VLM に記述させる。簡潔な言語記述で再現できてしまう候補（例：「赤と青のT字接合」と言えば済むもの）は除く。どう担保するかは ChatGPT への検討依頼事項（§8）。
  - 統制として、名前のある新概念（例：「星形を含む」）も用意する。
- **データ量**：新概念の正例・負例を各 50、100、200 枚の3段階で用意する（標本効率の曲線を描くため）。
- **分割**：train（Agentが見る）、dev（Agentが評価に使う）、held-out（封印する）、shift（分布シフト）。

### 4.2 モデル

- 3〜4層の小型CNN。BatchNorm なし。10⁴〜10⁵ パラメータ。
- 新概念用の出力ユニットを1つ追加し、重みは0で初期化する。
- 初期状態で X の AUROC ≈ 0.5 であることを確認する。

### 4.3 Agentへの課題

- 与えるもの：「この出力が、正例と負例を区別できるようにせよ」という指示、正例と負例の画像（train）、ツール群、予算。
- 与えないもの：X が何であるかの説明、held-out へのアクセス。

### 4.4 比較条件

| 条件 | 内容 | 検証する問い |
|---|---|---|
| **A. Full Agent** | VLM、全ツール | 主条件 |
| **B. 意味剥奪** | 画像を見せず、テンソル統計のみ。チャネル・出力は匿名ID | P1（意味知識の寄与） |
| **C. 内部観察剥奪** | 入出力と評価値、永続編集ツールのみ | P1（内部観察の寄与） |
| **D. ランダム編集** | 同じ操作空間・同じ予算 | 下限 |
| **E. ゼロ次最適化** | ES / CMA-ES。同じ操作空間（新チャネル＋接続）、同じ順伝播予算 | **P2（最重要）** |
| **F. Matched filter** | 正例パッチ平均 − 負例パッチ平均をカーネルとし、閉形式の読み出し | 固定則で十分ではないか |
| **G. 逆伝播** | 同じパラメータ部分だけを SGD で学習 | 上限の参考 |
| **H. 当てはめ禁止の Agent** | A から最小二乗・回帰などを全面禁止 | RQ3（固定則への退化） |

最初の実行は、**A, C, E, F の4条件**に絞る。結果を見て B, D, G, H を追加する。

### 4.5 計測項目

- 新概念の AUROC（dev／held-out／shift）
- 基礎概念の精度の変化（保持）
- Agentを外した状態での性能
- 順伝播回数、評価回数、トークン数、壁時計時間、費用
- 編集の構造（変更パラメータ数、追加チャネル数）
- ledger 上の説明の忠実性（説明した役割をアブレーションで確認できた割合）
- 当てはめ演算のフラグ数
- 分散：モデル初期化 × Agentの乱数 × X の種類で、それぞれ複数

## 5. 成功の判定基準（実験前に事前登録する）

数値はパイロット（E0）の後に確定し、E1 の実行前に固定する。以下は暫定値である。

| 項目 | 暫定基準 |
|---|---|
| 獲得（L1） | held-out の AUROC ≥ 0.90 |
| 汎化（L3） | shift の AUROC ≥ 0.80 |
| 保持（L4） | 基礎概念の精度低下 ≤ 2 ポイント |
| 永続性（L2） | Agentを外した状態で上記を満たす |
| 情報源への依存（P1） | A と B（または C）の AUROC の差が、シード間で有意（事前に検定法を固定） |
| 標本効率（P2） | 同じ順伝播予算で、A の AUROC が E を有意に上回る。または、同じ AUROC に到達するまでの順伝播回数が E の 1/10 以下 |
| 固定則への退化の否定 | A の解が F と有意に異なり、かつ H でも A と同等の性能が出る |

**判定の運用ルール**

- held-out は判定時に一度だけ開ける。
- 失敗した試行も含めて、すべての試行を記録・報告する。
- 基準は結果を見てから変更しない。変更する場合は、その理由とともに版を上げる。

## 6. 主なリスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 同じ問いを扱う論文が先に出る | 新規性の喪失 | arXiv を週次で監視する。重なったら RQ2・RQ4 へ重心を移す |
| 名前のない概念が、実は言語で記述できる | P1 の判定が無効になる | VLM による事前の記述テストで候補を選別する |
| Agentがコード内で固定則を実装する | RQ3 の判定が濁る | 演算の計量・フラグ付け、条件 H |
| dev への過適合 | held-out で性能が出ない | held-out の封印、評価回数の予算 |
| ツールの出来が結果を左右する | 原理の効果とツールの効果が分離できない | ツール単位のアブレーション、ツール仕様の固定と公開 |
| 費用 | 試行回数が足りない | 最初は4条件に絞る。モデルを小さく保つ |
| 結果が否定的になる | 「ADLは成立しない」 | 否定的な結果を、WSPの限界の体系的検証として整理する。研究としての価値は残る |

## 7. 直近のタスク

1. Ropinski & Kranz（2611.26408）と iWSP（2611.18114）を精読し、E1 との重なりを確認する（G0）。
2. ツール群と計量・監査の最小版を設計し、実装する。
3. データ生成器を作り、名前のない概念の候補を作って VLM で記述テストを行う。
4. ベースCNNを学習・凍結し、E0 を実行する。
5. E0 の結果から判定基準を確定し、事前登録してから E1 を実行する。

実装と実験を進めるには、コードを置くリポジトリと、実験を実行する環境（GPUの有無、使うLLM/VLMのAPI）を決める必要がある。

## 8. ChatGPT との検討事項

1. **§2.2 の「学習主体」の定義**（P1・P2）は妥当か。他に必要な条件はあるか。
2. **§2.3 の許容・禁止の線引き**。特に、Agentのコード内での最小二乗を「Agentの推論」として認めるべきか。
3. **名前のない概念の作り方**（§4.1）。VLM の記述テスト以外に、より厳密な担保の方法はあるか。
4. **§5 の判定基準の数値**。特に P2（ES との比較）を公平にするための予算の揃え方。
5. **Stage 2 が不成立だった場合**に、研究として最も価値のある方向はどこか。

## 9. 確認された事実・仮説・未解決事項の区別

- **確認された事実**：WSP の一連の研究と、その限界の記述（報告第1版 §1.1、§6）。
- **研究仮説**：H1（探索次元の削減）、H2（意味的 credit assignment）、H3（反仮説：既知特徴の再生のみ）。
- **未検証の提案**：本方針書のツール設計、実験 E0〜E4、判定基準。
- **実験によって確認された結果**：まだない。
- **未解決事項**：入力勾配の扱い、当てはめ演算の扱い、名前のなさの担保方法、実行環境。
