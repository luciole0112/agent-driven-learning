## 0. 要点

1. **目的は「Agent による weight space programming」。** 軸は2つで、両方を行う。
   - **軸2「獲得」**：Agent がデータ（誤分類画像など）から、名前のない特徴を見つけ、重みに書き込む。
   - **軸1「解釈・改変」**：Agent が既存フィルタの機能を推定し、因果的な介入で検証してから、その機能を強める・弱める・変えるように書き換える。
   - 初期は軸2を主に進め、精度が上がった段階で軸1の比重を上げる（ユーザーの方針どおり）。
2. **モデル①（事前学習済み）は、S1 から始める。** S1 は「ImageNet で事前学習した本体（凍結）＋ CIFAR-10 用のヘッドだけを逆伝播で学習した線形プローブ」で、**本体の CIFAR-10 への fine-tune はしない**。誤りが十分に残るので軸2の余地があり、ヘッドは既存特徴の最適な線形読み出しなので、「Agent の改善が既存特徴のつなぎ替えではない」ことを示しやすい。fine-tune 済みの S2 は、軸1の段階で使う。
3. **モデル②（ランダム初期化）は、非常に難しい。到達目標は控えめに置く。** 約224万パラメータ（10クラスのヘッドの場合。ImageNet 用 1000 クラスなら約350万）を、勾配なしで一から書き上げるのは現実的でない。②では「下の層から順に、少しずつプログラムする」段階的な課題にして、**同じ予算の ES と、勾配なしの固定則（BN 統計の再推定＋最近傍クラス平均）を上回ること**を主な目標にする。逆伝播並みの精度（90%以上）は目標にしない。
4. **ラベルの扱い**：学習用（train）のラベルは使う（教師あり。ES・逆伝播と同じ条件で比べるため）。dev は集計値（正解率、クラスごとの正解率、混同）だけを見せ、test（heldout）と破損画像（shift）は封印する。ラベルなしの条件は発展課題とする。
5. **比較は同じ予算でそろえる。** 共通の単位は「ネットワークに通した画像の枚数（forward_images）」。逆伝播は、1枚を3枚分（順伝播1＋逆伝播2）として数える。dev の評価回数も同じ上限にする。
6. **環境は実装済み**（`adl/env/mbv2_env.py` ほか、§8）。クラウドからは CIFAR-10 と ImageNet の重みを取得できないため、動作確認は同じ形の代替データとランダムな重みで行った。実データでの実行は、ユーザーの PC（RTX 4060）で行う。

## 1. 研究の問いと、この実験で答えること

| ID | 問い | 実験 |
|---|---|---|
| Q-A（軸2） | Agent は、凍結した既存特徴の線形読み出しでは取れない誤りを、新しい特徴を書き込むことで減らせるか | ①-E1、②-E3 |
| Q-B（軸1） | Agent は、フィルタの機能を、介入結果を事前に予測できる程度に正しく推定できるか。推定に基づく書き換えは、狙った効果を、狙った範囲だけに生むか | ①-E2 |
| Q-C（スケール） | ランダムな 224 万パラメータのネットワークに、勾配なしで、どこまでの能力を書き込めるか。どの層を Agent が書くと効くか | ②-E3 |
| Q-D（学習主体） | 上の成果は、意味情報・内部観察に依存しているか（P1）。同じ予算のゼロ次最適化を上回るか（P2） | 全実験の比較条件 |

「学習した」「学習主体である」の定義（L1〜L4、P1〜P2）は研究方針書 v1 §2 をそのまま使う。CIFAR-10 用に読み替えた点は §5 に書く。

## 2. 共通の設定

### 2.1 データ分割

| 分割 | 中身 | Agent に見えるもの |
|---|---|---|
| train | 公式 train 50,000 枚のうち 45,000 枚 | 画像、正解ラベル、モデルの予測。観察ツールは先頭 5,000 枚（pool）で計算する。末尾 1,000 枚は「保持の監視用（retention）」で、Agent には見せない |
| dev | 公式 train の残り 5,000 枚（クラスごとに 500 枚） | 集計値だけ（正解率、NLL、クラスごとの正解率、混同行列）。画像は見せない |
| heldout | 公式 test 10,000 枚 | 封印。`submit` の後に採点するだけ |
| shift | test 画像に、ノイズ・ぼかし・低コントラスト・明るさの4種の破損を、決まった乱数で加えたもの | 封印。分布シフトへの汎化（L3）を測る |

### 2.2 研究ルール（実装で強制するもの）

- 対象モデルのパラメータは勾配を持たない（全ツール呼び出しの後に検査する）。
- `probe`（一時的な介入）は、モデルを変えない。永続的な編集は `edit` 系のツールだけで行い、予算を消費する。
- サンドボックス（NumPy のみ）の最小二乗・逆行列・反復更新ループは、自動で検知して記録する。全面禁止にする条件（H）も設ける。
- BN 統計の再推定（`recalibrate_bn`）は、順伝播だけで行う固定的な統計規則なので、使ったことを記録する（`fixed_rule:bn_recalibration`）。
- 環境側の「計測器」：`probe_readout`（ある層の活性から 10 クラスを線形に読めるかを、環境が閉形式のリッジ回帰で測る）。モデルは変わらず、評価1回として数える。Agent が自分で当てはめをするのとは区別して記録する。

### 2.3 Agent の方式

- PR 5 で成功した方式を使う：**Claude 自身が Agent になり**、ツール呼び出しを `actions.json` に書き、`scripts/mbv2_agent_session.py` が環境を作り直して全手順を再生する。有料 API は不要。
- 毎回の編集は、研究方針書のプロトコル（観察 → 仮説 → 1回の編集 → dev で評価 → 採否の決定）に従う。①では、保持用の正解率が初期値から 2 ポイント以上下がる編集を自動で取り消す。②は守る能力がまだないので、この自動取り消しは使わない。
- 注意：再生のたびに全手順の順伝播をやり直す。CPU では pool と dev を小さくするか、GPU で実行する。

### 2.4 Agent が使えるツール（MobileNetV2 用）

| 種類 | ツール | 内容 |
|---|---|---|
| 構造 | `inspect_model` | 層の一覧（stem、bK.expand／dw／project、last、head）、残差の有無、受容野、予算 |
| 観察 | `confusion`、`show_examples` | 混同行列、クラス・予測クラス・誤りで絞った train 画像 |
| 観察 | `render_kernels` | stem は RGB タイル、depthwise は 3×3 の図、1×1 と head は重みの行。**BN を畳み込んだ実効カーネル**を既定で表示する |
| 観察 | `top_activations`、`feature_map`、`channel_stats` | 最も強く反応する受容野の切り出しとクラスの内訳、活性マップ、クラス選択性（または2クラス間の d′） |
| 観察 | `stimulus_response` | 合成刺激（8方向×3周期の縞、単色、点・輪・四角）への応答と方位の同調曲線。軸1の仮説検証用 |
| 因果 | `probe` | チャネルの活性を一時的に何倍か（0 なら除去）にして、クラスごとの正解率の変化を見る |
| 計測 | `probe_readout` | 層の活性からの線形読み出しの dev 正解率（環境が測る） |
| 数値 | `capture_activations`、`run_sandbox` | 活性をサンドボックスに取り出し、NumPy で解析する |
| 編集 | `set_weights`、`add_to_weights`、`scale_channel`、`lowrank_update` | 値の書き込み・加算、チャネル出力の拡大縮小（BN の γ・β を変える）、1×1 と head への低ランク更新 |
| 編集（構造） | `add_hidden_channel`、`remove_hidden_channel` | ブロック K の展開層にチャネルを1本足す（expand の行、depthwise の 3×3、project の列）。project の列を 0 にすれば機能は変わらない |
| 編集（構造） | `add_feature_channel` | `last`（320→1280）にチャネルを1本足し、head の列を付ける |
| 編集 | `recalibrate_bn` | BN 統計の再推定（固定則として記録） |
| 検証・記憶 | `evaluate`、`checkpoint`、`rollback`、`diff`、`note`、`hypothesis`、`decide`、`submit` | 従来どおり |

MobileNetV2 に特有の扱い：

- **depthwise／pointwise**：depthwise はチャネルごとに 3×3 が1枚なので、「このフィルタは何を抽出するか」を直接読める。pointwise はチャネルの混ぜ方なので、重みの行（どの入力をどの符号で使うか）として見せる。
- **BatchNorm**：推論モードの BN は、畳み込みに畳み込める（W′ = W·γ/√(σ²+ε)、b′ = β − μ·γ/√(σ²+ε)）。表示は実効カーネル、チャネルの強弱は γ・β で変える。重みを書き換えた後に BN 統計が古くなる問題は、`recalibrate_bn` で扱う。
- **残差**：project の出力は活性化関数を通らず、入力に足される。`bK.out` で足し算の後の活性を見られる。`add_hidden_channel` で足したチャネルは、残差の枝にだけ入るので、project の列を小さく始めれば既存の機能を壊さずに試せる。

## 3. モデル①：事前学習済み MobileNetV2

### 3.1 出発点（どこから始めるか）

| 名前 | 作り方 | 用途 |
|---|---|---|
| S0 | ImageNet 重み（torchvision、IMAGENET1K_V1）の本体 ＋ 0 で初期化した 10 クラスのヘッド。入力は 32px を 128px に拡大 | 参照（正解率 10%） |
| **S1** | S0 の本体を凍結し、ヘッドだけを逆伝播で学習（線形プローブ） | **①の主な出発点**（軸2） |
| S2 | S1 を CIFAR-10 で全体 fine-tune（逆伝播、10 エポック相当） | 軸1の段階の出発点 |

S1 を主な出発点にする理由：

- **利点**：(a) 誤りが十分に残る（実測待ち。予想では 80〜88% 程度）ので、軸2の改善の余地がある。(b) S1 のヘッドは「既存特徴の最適な線形読み出し」に近い。したがって S1 からの改善は、ヘッドのつなぎ替えではなく、**本体に新しい特徴を足したこと**によるものだと言いやすい。(c) ImageNet で学んだフィルタは機能がはっきりしていて、軸1の素材になる。
- **欠点**：(a) ImageNet には犬・猫・車などがあり、CIFAR-10 の概念の多くが「名前のある既存特徴」として本体に入っている。新しい特徴の獲得なのか、眠っていた特徴の掘り起こしなのかを区別する必要がある（§3.4 の対照で扱う）。(b) 128px への拡大で計算が重くなる（32px の約16倍）。224px は ImageNet 本来の解像度だが、さらに約3倍重いので、v1 では 128px にする。
- **S2 を軸2の出発点にしない理由**：fine-tune で誤りの大半が消え、残る誤りはラベルの曖昧な画像に偏る。Agent が足せるものが少ない。軸1の「精度が上がった段階」には S2 が合う。

逆伝播を使うのは、出発点を作るときだけ（研究方針書の「ベースモデルの事前学習は許容」に当たる）。Agent の実行中には使わない。

### 3.2 実験 ①-E1（軸2：誤りからの獲得）

- **課題**：S1 の混同が大きいクラス対（猫↔犬、自動車↔トラック、鹿↔馬、鳥↔飛行機などから、Step 0 の実測で 2〜3 対を事前に決める）について、その対の誤りを減らす。
- **Agent が観察するもの**：対象の対の誤分類画像と正しく分類された画像（`show_examples`）、両クラスを分けるチャネル（`channel_stats` の d′）、その反応の中身（`top_activations`、`feature_map`）。
- **Agent が書き換えるもの**（推奨の順）：
  1. 後段のブロック（13〜17）の展開層に、新しいチャネルを足す（`add_hidden_channel`）。中身は、Agent が見つけた「対を分ける手がかり」を検出するように設計する（入力チャネルの組み合わせ、3×3 の空間パターン）。
  2. `last` に特徴チャネルを足し、対象の2クラスの head 重みだけを付ける（`add_feature_channel`）。
  3. 既存のチャネルの強弱（`scale_channel`）、pointwise の低ランク更新。
- **成功の判定**（heldout で、事前に固定する）：
  - (L1) 対象の対の誤り（2クラスの画像のうち、相手のクラスに分類された割合）が、S1 から有意に減る（対応のある McNemar 検定、p < 0.01）。
  - (L4) 全体の正解率が S1 から 0.5 ポイント以上下がらない。対象外のクラスの正解率も、それぞれ 1 ポイント以上下がらない。
  - (L3) shift でも、対の誤りが減る方向である。
  - (L2) Agent を外した後も（重みとして）効果が残る。これは仕組み上、常に満たす。
- **新規性の対照**：S1 のヘッドを、同じ予算の逆伝播で追加学習した「ヘッドのみ」の参照。これで取れる改善は、既存特徴の読み出しで足りる部分である。Agent の改善がこれを上回ったときだけ、「新しい特徴を足した」と主張する。

### 3.3 実験 ①-E2（軸1：解釈と改変）

- **出発点**：S2（S1 でも行い、比べる）。
- **手順**（1つのフィルタごと）：
  1. **推定**：Agent がフィルタ（depthwise の 3×3、または pointwise のチャネル）を選び、機能を文章で書く（例：「b3.dw[17] は赤と緑の境界の水平エッジを抽出する」）。
  2. **予測を登録**：(a) `stimulus_response` で最もよく反応する刺激、(b) `probe` で除去したときに、どのクラスの正解率が下がるか（上位3クラスと、下がる量の大小）、を検証の前に `hypothesis` に書く。
  3. **因果的な検証**：`stimulus_response` と `probe` を実行し、予測と照合する。外れたら推定を直すか、そのフィルタを諦める。
  4. **改変**：推定した機能を「強める」（例：3×3 の形を鋭くする、γ を上げる）、「弱める」、「変える」（例：方位を回す）。改変の前に、狙った効果（どのクラスがどれだけ変わるか）を予測する。
  5. **評価**：dev で評価し、採否を決める。
- **成功の判定**：
  - 解釈の正しさ：除去の効果（下がるクラスの上位3つ）の予測の的中率が、`channel_stats` だけから機械的に作った予測（選択性の高いクラスを並べるだけ）を上回る。
  - 改変の効果と特異性：改変が狙ったクラスを、予測した方向に動かし、それ以外のクラスへの影響が小さい（狙ったクラスの変化 ÷ 他クラスの変化の絶対値の平均）。同じ大きさのランダムな改変と比べる。
  - これは「何を抽出しているかを推定し、その機能を強化する」という、ユーザーが例に挙げた操作をそのまま測るものである。

### 3.4 ①の比較条件

| 条件 | 内容 |
|---|---|
| A. Full Agent（Claude） | 全ツール |
| B. 意味剥奪 | 画像を見せない（`condition=no_semantics`） |
| C. 内部観察剥奪 | 観察ツールなし（`condition=no_observation`） |
| D. ランダム | 同じ操作空間で、ランダムな摂動を試して良くなれば残す（山登り） |
| E. ES | 同じ操作空間で、OpenAI-ES（対称なサンプル、順位による正規化） |
| F. 固定則 | ヘッドの最近傍クラス平均、リッジ回帰（閉形式） |
| G. 逆伝播 | 同じ操作空間（上限の参照）、ヘッドのみ（新規性の対照）、全体（S2 に相当） |
| H. 当てはめ禁止の Agent | A から最小二乗・回帰などを禁止 |

「同じ操作空間」は、Agent の実行が終わった後に、Agent が実際に触ったテンソルの集合（`diff` で分かる）に合わせる。たとえば Agent がブロック 16 に k 本のチャネルを足したなら、ES と逆伝播にも同じ k 本を足した空間で探索させる。

## 4. モデル②：事前学習なし（ランダム初期化）の MobileNetV2

### 4.1 難しさの正直な評価

- **規模**：CIFAR 用の構成（stem と最初の 24 チャネルのブロックを stride 1 にしたもの）で、10 クラスのヘッドを含めて 2,236,682 パラメータ。値を1つずつ書くことは不可能で、ES も、この次元数では探索の効率が非常に悪い。
- **実測した最初の障害：信号が消える。** ランダム初期化の BN 統計（平均 0、分散 1）のまま推論すると、層を進むごとに活性が小さくなり、最後の層では約 10⁻⁹ になる。出力はすべての画像でほぼ同じで、どのクラスにも分類できない。BN 統計を順伝播だけで再推定すると、全層で 0.15〜0.4 程度に戻る（代替データでの測定。下表）。したがって②では、BN 統計の再推定が「スタートラインに立つための前提」になる。

| 層 | 平均絶対活性（初期化のまま） | BN 統計を再推定した後 |
|---|---|---|
| stem | 1.4×10⁻¹ | 4.0×10⁻¹ |
| b5.out | 4.7×10⁻⁴ | 1.7×10⁻¹ |
| b13.out | 1.9×10⁻⁶ | 2.4×10⁻¹ |
| last | 8.5×10⁻¹⁰ | 3.9×10⁻¹ |

- **勾配なしで CIFAR-10 に届いた既存の例**：Coates・Lee・Ng（AISTATS 2011）は、k-means で学んだ単層の特徴と線形分類器で約 80% を報告している。Oyallon・Mallat（CVPR 2015）は、手で設計したウェーブレットの散乱変換で 80% 台前半を報告している（どちらも、具体的な数値は記憶によるもので、原文での確認が必要）。どちらも MobileNetV2 ではなく、特徴の数も大きい。ただし「逆伝播なしで設計・統計則から作った特徴でも、CIFAR-10 で相当な精度が出る」ことは示している。これは同時に、**Agent の成果を固定則と比べる必要がある**ことも意味する。
- **結論**：②で「Agent が全層を書いて、逆伝播並みの精度に達する」ことは目標にしない。下から順に書く段階的な課題にし、各段階で、同じ予算の ES と固定則を上回るかを問う。

### 4.2 出発点

| 名前 | 作り方 |
|---|---|
| R0 | ランダム初期化（seed ごと） |
| R0c | R0 の BN 統計を、train 2,000 枚で再推定（順伝播のみ） |

②の比較はすべて R0c から始める。BN の再推定そのものは固定則なので、「R0c ＋ 固定則のヘッド（最近傍クラス平均、リッジ）」を最低限の基準（ランダム特徴の基準）にする。

### 4.3 実験 ②-E3（段階的なプログラミング）

各段階で Agent が書く範囲を決め、それより上の層はランダムのまま（BN 統計だけは再推定する）にする。評価は (a) その段階の層からの線形読み出し（`probe_readout`、環境が測る）と、(b) 最終出力の正解率（ヘッドは固定則か Agent が書く）の2つで行う。

| 段階 | Agent が書く範囲 | 値の数 | 想定する Agent の戦略 |
|---|---|---|---|
| ②-a | stem（3×3×3 のフィルタ 32 本） | 864 ＋ BN 64 | 名前のある特徴：方位ごとのエッジ、色の反対色、中心周辺型。`stimulus_response` で設計どおりか確認する |
| ②-b | ブロック 1〜3 の depthwise と pointwise | 約 1.5 万 | 名前のない特徴：train の小領域を Agent が観察してまとまりを見つけ、それを検出するチャネルを書く（軸2） |
| ②-c | 後段の展開層へのチャネル追加と head | 段階に応じて | ①-E1 と同じ方法で、誤りの対を減らす |

- **成功の判定**（heldout）：
  - ②-G1：各段階で、R0c（その範囲がランダムのまま）の線形読み出しを有意に上回る。
  - ②-G2：同じ範囲・同じ予算の ES とランダム探索を上回る（P2）。
  - ②-G3：同じ範囲・同じ予算の逆伝播（上の層はランダムのまま）との差を報告する。これは上回ることを目標にせず、差の大きさを記録する。
  - 目標の数値（たとえば「②-a で線形読み出し +x ポイント」）は、Step 0 で R0c と ES の実測値を見てから決める。
- **やらないこと（v1）**：Agent が全 224 万パラメータを書くこと。幅の縮小（width_mult）や層の削除は、MobileNetV2 を使うという前提を変えるので行わない。必要になった場合は、ユーザーに確認する。

### 4.4 ②の比較条件

①と同じ A〜H を、段階ごとの操作空間で行う。逆伝播は、BN を学習モードで使う（ランダム初期化からは、これがないと学習が進まないため）。ES では、数世代ごとに BN 統計を再推定する設定も試す（再推定に使った画像も予算に数える）。

## 5. 予算と評価の作法

### 5.1 予算

- **共通の単位**：`forward_images`（ネットワークに通した画像の枚数）。
  - Agent：観察・介入・評価のすべての順伝播を数える。同じモデルの状態では、pool の予測と活性を使い回す（ES も同じ状態を2回評価する必要はないので、公平である）。
  - ES：1世代で、個体数 × ミニバッチの枚数。
  - ランダム：1手で、2 × ミニバッチの枚数（現状と候補を同じバッチで比べる）。
  - 逆伝播：1ステップで、3 × ミニバッチの枚数。
- **dev の評価回数**：Agent は 60 回まで。ES とランダムは、dev を探索に使わない（train のミニバッチの損失を使う）。dev は記録のためだけに測り、予算には数えない。
- **予算の段階**：50 万、200 万、800 万枚の3段階を仮に置き、Step 0 で GPU の処理速度を測って確定する。Agent の実際の制約は、Claude の1回のセッションで扱えるツール呼び出しの数（100〜200 回程度）になると予想する。

### 5.2 統計

- 比較手法：seed 3つ以上。Agent：まず条件ごとに1回、結果が有望な条件で追加する。
- heldout の予測は対応があるので、2つの手法の比較には McNemar 検定を使う。正解率の信頼区間はブートストラップで出す。
- 全ての判定基準は、Agent の実行前にこの文書の改訂として固定する（事後の基準変更を避ける）。

## 6. 交絡とリスク

| 項目 | 内容 | 対策 |
|---|---|---|
| ImageNet との重なり | ①では、CIFAR-10 の概念の多くが本体に既にある。獲得ではなく掘り起こしかもしれない | ヘッドのみの逆伝播を対照にする。Agent が足したチャネルについて、S0 の既存チャネルとの相関を測る |
| dev への過適合 | 評価を繰り返すと、dev に合わせた編集になる | 評価は 60 回まで。判定は heldout のみ |
| BN の扱い | 重みを書き換えると、BN 統計が古くなる | 実効カーネルで表示する。再推定は固定則として記録し、使った回数を報告する |
| 固定則への退化 | Agent がサンドボックスで回帰や k-means を書けば、それは Agent の学習ではない | 監査フラグを数え、条件 H と比べる |
| 再生のコスト | 再生のたびに全手順の順伝播をやり直す | GPU で行う。重い場合は、途中の状態を保存して再開する機能を次に作る |
| 入力の拡大 | 128px は ImageNet の本来の 224px より小さく、事前学習の特徴が少し弱まる | S1 の精度を見て、必要なら 160px か 224px に変える |

## 確認された事実

- 環境、比較手法、出発点を作るスクリプトは、代替データで動く。
- ランダム初期化の MobileNetV2 は、BN 統計を再推定しないと、出力層で活性が約 10⁻⁹ まで消える。再推定すると全層で 0.15〜0.4 程度に戻る（代替データ）。

## 研究仮説

- ①では、ImageNet の既存特徴の線形読み出し（S1）で取れない誤りを、Agent が後段に足したチャネルで減らせる。
- ②では、Agent が名前のある特徴（方位・色）で stem を設計すると、同じ予算の ES を上回る。名前のない特徴が要る中間層（②-b）では、その差は小さくなる、あるいは逆転する。

## 未解決事項

- 予算の段階と、②の数値目標。
- Agent のセッションの長さ（ツール呼び出しの数）が、予算より先に制約になるかどうか。

- ①の出発点を S1（fine-tune なし、線形プローブのみ）にした理由（§3.1）と、新規性の対照（ヘッドのみの逆伝播、§3.2）。
- ②の到達目標を「ES と固定則を上回る」に絞った理由（§4.1）。逆伝播並みは目標にしない。
- 予算の単位を `forward_images` に統一し、逆伝播を3倍で数える作法（§5.1）。
